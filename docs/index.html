A wrong answer that survives review

An assistant asked about rupture disks answered about pressure relief valves. Fluent, well formatted, and inapplicable to the device in front of the engineer.

That substitution is the predictable output of retrieval with no authoritative binding, and the public data most people would use to check such a system has a defect large enough to move a national injury rate by a factor of 249 in one year. This is the research programme built in response, together with what it does not yet establish.

01

The failure this starts from

An engineer asks a configured assistant how to size overpressure protection for a reactor protected by a rupture disk. The system answers about a spring-loaded pressure relief valve.

What was asked about

A rupture disk. A one-shot non-reclosing device with a marked burst pressure, a burst pressure tolerance, a manufacturing design range and an operating ratio.

Once it opens, it stays open. The design question is how much margin to keep between normal operating pressure and the burst pressure, because running close to the burst pressure fatigues the disk.

What came back

A spring-loaded pressure relief valve. Set pressure, blowdown, reseating, chatter.

These are the parameters of a device that recloses. A rupture disk has none of them, because it does not reclose. The answer was internally consistent and correctly formatted throughout.

The two devices are taxonomic siblings under "pressure relief device", so the answer reads as on-topic. Their parameter spaces do not intersect, so the answer cannot be converted into the right one by adjustment.

There is no arithmetic that converts one answer into the other. Error class: co-hyponym substitution

This is the error class the benchmark measures. It is more dangerous than an obviously wrong answer precisely because it survives casual review: a reader without device-specific background sees correct vocabulary, correct format, and a confident tone. One documented case is not a measured rate. Measuring the rate is what the benchmark exists for, and that has not been done yet.

02

Why it is structural, not unlucky

Four mechanisms converge on the same output. None of them is a defect in a particular model, so none of them is fixed by changing model.

1

There was no retrieval

A system prompt plus pasted reference text is parametric conditioning, not retrieval-augmented generation. There is no index, no retriever, and no marginalisation over retrieved documents. It shifts the prior. It does not supply evidence.

2

The correct content is long tail

Relief valve material fills vendor catalogues, sizing tutorials and forum threads. Rupture disk material does not. Parametric factual accuracy tracks pretraining frequency, so a sparse query returns the dense neighbour.

3

Abstention is penalised

Training objectives and benchmark scoring reward a plausible guess over an admission of uncertainty. Under uncertainty the system emits its highest-probability plausible completion, which is exactly the adjacent wrong answer.

4

The authoritative corpus is lexically adversarial

API 520 Part I documents both device types in one standard with a shared definitions section, and the word "disc" is polysemous inside it: in a relief valve the disc is the closure element, while a rupture disk is a whole device. Chunk and embed an index over that document and the nearest neighbours of a rupture disk passage are relief valve passages. ISO splits the two across separate parts, 4126-1 for safety valves and 4126-2 for bursting discs, while ASME and API co-locate them. Which standards family gets indexed is therefore a safety-relevant corpus design decision, and it argues for device-type metadata filtering over undifferentiated top-k retrieval.

The failure is a predictable interaction between embedding geometry and the terminology of the source corpus. Naming it that way, rather than as a model defect, is what makes it something an architecture can be held to.

03

The data underneath is no better

If the answer to ungrounded generation is grounding in data, the data has to hold. Nine calendar years of OSHA Injury Tracking Application filings, 2,801,064 records after deduplication, say it does not hold as filed. A system trained or benchmarked on these numbers as they arrive inherits both errors at once.

What was built in response

Six repositories, each answering one part of the argument above. Each card states what the project establishes and what it does not, because the subject here is systems that overclaim.

ehs-ai-grounding-eval

A question corpus and scoring harness for whether an answer is bound to an authoritative source or generated from parametric memory. 68 items across eight regulatory domains, 23 complete minimal pairs whose stems differ only in the entity asked about, so a system that succeeds by topical similarity fails visibly. The primary statistic is paired accuracy: both members of a pair correct, or neither counts.

EstablishesThe apparatus and the corpus. Every item carries a public source clause with a verbatim anchor span; six drafts whose sources could not be verified were quarantined rather than shipped.
Does notNo system has been evaluated. There are no baseline results. Every number the code prints out of the box comes from a mock fixture that labels itself as one.

ehs-human-factors-ontology

A hand-written OWL/Turtle encoding of the four-context performance-influencing-factor structure, an explicit crosswalk to SPAR-H, CREAM, HFACS and the HSE PIF list, and a dependency-free forward-chaining engine with stratified negation. Every derived fact records the rule that produced it and the facts that satisfied that rule, so a conclusion unwinds to the scenario inputs and the cited literature.

EstablishesThe encoding, the crosswalk and the traceability. The crosswalk is generated from the Turtle and the test suite fails if the two disagree, so they cannot drift apart.
Does notThe taxonomy is adopted, not new: the four contexts and twenty factors are IDHEAS-G's, taken unchanged and cited. Factor levels in the worked scenarios are analyst-assigned, not measured.

A safety control competes for capital against projects that can quote a return, and the costs it avoids are usually counted in one narrow way. This calculator runs the same investment twice, once on directly booked costs and once with human-capital costs added, and shows the difference. Four lines of arithmetic, plus tornado sensitivity and a Monte Carlo mode. Includes a single-file browser calculator with no build step and no network calls.

05 · The paper · draft

Grounded reasoning for safety-critical AI

An ontology-based architecture and evaluation benchmark for human error risk assessment in process industries.

The argument runs in four parts. That ungrounded retrieval fails structurally rather than incidentally on safety-critical technical queries. That contextual human-error factors can be encoded as an auditable ontology mapped honestly onto forty years of prior performance-shaping-factor work. That grounding can be measured rather than asserted. And that the quality of the data underneath decides whether any of the rest survives contact with a real deployment.

06

What is still missing

The subject of this work is whether AI systems overclaim. A page that overclaimed about them would refute itself, so here is the ledger.

Open, unresolved, and being worked on

  • No baseline results The benchmark contributes apparatus and a question corpus. No system has been run against it, so there is no grounded-versus-ungrounded comparison to report. Until that run exists, the claim that grounding can be measured is a claim about a method, not a result.
  • Reviewers would reject An internal adversarial review has been run against the current manuscript. Four of five reviewers would reject it, principally for bundling four separable contributions into one paper and for presenting a benchmark with no baseline results. The formal-methods reviewer did not reject. Both findings are being acted on.
  • Citation audit Every citation in the manuscript is checked against a primary or publisher-of-record source, and the check is committed: paper/citations_verified.json holds 198 entries, each with the evidence URL used, and 162 of them carry a note recording what the check changed. The reference builder refuses to emit a citation that has no entry. Earlier drafts carried a wider reference set from which one fabricated citation was found and removed and a number of others were judged to overstretch their source and were rewritten or dropped; those draft-stage counts are not preserved in a committed artifact, so they are not quoted here.
  • Ontology inputs are assigned Factor levels in the worked scenarios are set by an analyst, not measured from an instrument or elicited from a panel. The engine's traces show how a conclusion follows from those levels. They do not make the levels correct.
  • Simulation is not evidence The SEM work is entirely synthetic by design, and the benchmark's demonstration run is a fixture. Neither is reported anywhere as a finding about the world. Where synthetic data appears in a repository it lives in a synthetic/ directory next to its generator.
  • One case is not a rate The rupture disk substitution in section 01 is a single documented failure. It motivates the work and it illustrates the error class. It does not establish how often the class occurs, which is the question the benchmark was built to answer and has not yet answered.
